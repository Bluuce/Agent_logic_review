# Agent Logic Review

[English](README.en.md) · 实验性 **v0.1.0** · [MIT](LICENSE)

在 Agent 采用关键结论或宣布任务完成前，检查现有证据究竟支持什么。提供**满分100的总分、可核查依据和最小修正**，也支持事后审查 AI 回答。

## 先看一个例子

**设计示例，非实测输出。** 验收清单要求正常登录和会话过期两个场景都通过。Agent 只看到正常登录测试通过，就说“认证功能已全部验收”。

> **总分：50/100 · 部分支持**  
> **核心主张：**认证功能已全部验收。  
> **依据与问题：**登录通过记录支持“登录场景通过”。清单还要求会话过期测试，现有完整记录没有该项结果；尚不能宣布整体验收。  
> **最小修正：**正常登录场景已通过；整体验收尚缺会话过期测试。  
> **下一步：**保留登录结果，补查会话过期，再判断整体验收是否完成。

## 适合什么任务

- **回答审查：**检查回答、论证、方案和完成声明中的关键推断。
- **阶段纠错：**在依赖一个中间结论继续任务前自检；修正后同步更新受影响的后续结论。

首版聚焦证据到结论的跳跃：局部测试冒充整体验收、工具调用成功冒充目标达成、未经核验的前提驱动行动，以及修正中间结果后遗留旧计划。

这是指导当前 Agent 的 skill。自动发现与调用取决于宿主；它不保证逐步拦截，不是后台监控，也不访问隐藏思维链。没有模型训练、Jev API、外部服务或自动 Hooks。工具能力与访问权限由宿主提供，正常模型使用仍受宿主的账号与费用规则约束。

## 在 Codex 中安装

本仓库以 Codex 为首个验证目标，实际验证状态见 [评测记录](evals/RESULTS.md)。其他宿主尚未验证。

下载或克隆仓库后，在仓库根目录执行下列命令，把 `/path/to/target-project` 换成目标项目的实际路径。适用于 macOS/Linux shell：

```sh
mkdir -p "/path/to/target-project/.agents/skills"
cp -R ./agent-logic-review "/path/to/target-project/.agents/skills/"
```

只复制 `agent-logic-review/` 技能目录，保留其内部相对路径；`evals/` 不是运行依赖。目标位置若已有同名 skill，先比较内容再更新。确认 Codex 能发现 `$agent-logic-review`；未出现时按宿主说明重新加载或重启。项目技能目录依据 [官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

## 调用方式

**回答审查**：

```text
使用 $agent-logic-review 审查以下回答，给出满分100的总分、依据和最小修正。
问题：认证功能是否全部验收？
验收要求：登录、会话过期两个场景都通过。
完整测试记录：仅运行登录测试，结果通过；没有运行会话过期测试。
AI回答：登录测试通过，因此认证功能已全部验收。
```

**阶段纠错**：

```text
使用 $agent-logic-review 的阶段纠错模式完成下面任务。
采用关键假设、依赖中间结果或宣布完成前进行检查；只展示简短依据。
题设每盒6个零件，买3盒，每人分3个。
我已有中间结论：3×6=21，所以能分给7人。先检查，再给最终人数。
```

第二例的原中间结论应被评为 **0/100**，随后修正为18个、6人。评分针对原主张，不因已经修正就把原评分改成100。

普通返回卡片包含：**总分、核心主张、依据与问题、最小修正、下一步**。没有错误时认可成立的论证，不强行找错；没有足够审查材料时说明具体缺什么。

## 总分怎么读

总分衡量**给定前提和证据，对核心主张实际表达的范围与确定性支持得有多充分**。它不是正确概率、置信度或写作评分。

| 总分 | 含义 |
| --- | --- |
| **0/100** | 核心论证被明确反例、矛盾、无效推断或决定性计算错误击穿 |
| **25/100** | 依据相关，但缺决定性前提或环节，尚未支持核心主张 |
| **50/100** | 支持有意义的较窄或较弱结论，原文扩大了范围或确定性 |
| **75/100** | 核心结论得到支持，存在可用已有材料修补的局部论证缺口 |
| **100/100** | 在声明的审查范围内，依据足以支持结论强度 |
| **暂不可评分** | 必要上下文或材料缺失，无法可靠判断；不给数字 |

只用这五个分数，不插值或编造置信度。多个关键主张取最低分，必要主张无法评估则总分暂不可评分，同时保留已知错误。**0分不证明结论必假，100分也不保证现实中所有前提都真。** 假设题可以按题设获得满分；事实核验状态单独说明。完整规则及边界例子见 [评分规范](agent-logic-review/references/rubric.md)。

不设“80分以上自动放行”。下一步依据具体问题决定：继续、修正或补证据。阶段纠错针对同一问题最多一次修正后复核，仍未解决就报告缺口。

## 评测与局限

首批 [案例](evals/README.md) 共12个：回答审查和阶段纠错各6个，开发集与留出集各6个。数据是项目作者编写的规格样例，并非独立专家标注或通用基准。不得把标准答案一起交给被评模型。

案例与结构检查不等于行为效果已经验证。实际运行状态、原始输出位置和失败项统一见 [评测记录](evals/RESULTS.md)。任何未完成的独立复核、基线对比或跨宿主验证都不视为通过；不声明准确率提升。

局限包括：主张提取可能漏掉关键条件；75与100等边界需要人工解释；宿主模型可能误判或漏做自检；缺少外部工具时只能在给定材料范围内审查。事实、数学与复杂领域问题需要合适证据，不能靠一个总分替代。
